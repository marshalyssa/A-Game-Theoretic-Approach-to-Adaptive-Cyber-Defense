## Overview

A game-theoretic cybersecurity decision agent that models attacker-defender interactions within the MITRE ATT&CK framework. Combines Bayesian inference (attacker-type identification), game theory (payoff-optimal mixed strategies via fictitious play), and reinforcement learning (Q-learning defender policy) to predict adversary behavior and recommend defensive actions. Supports two operational modes: synthetic simulation and live IOC analysis via real-time CTI feeds.

- **Purpose:** Bayesian belief update over attacker types using Bayes' theorem
- **Key functions:** `createBeliefState()`, `updateBelief()`, `decayBelief()`, `predictNextTechnique()`, `getBeliefEntropy()`
- **Math:** P(θ|obs) ∝ P(obs|θ) · P(θ), temporal decay toward uniform

#### game-engine.js
- **Purpose:** Payoff matrix construction + Nash equilibrium approximation via fictitious play
- **Key functions:** `computeDefenderUtility()`, `computeAttackerUtility()`, `computePayoffMatrix()`, `solveMixedStrategy()`, `rankDefenderActions()`
- **Math:** U_D = w₁·P(detect) + w₂·P(prevent) − w₃·cost − w₄·disruption

#### rl-agent.js
- **Purpose:** Tabular Q-learning defender agent with ε-greedy exploration
- **State space:** 14 tactic phases × 4 belief buckets × 3 severity × 3 criticality × 15 actions = 7,560 states
- **Key functions:** `createAgent()`, `selectAction()`, `updateAgent()`, `decayEpsilon()`
- **Math:** Q(s,a) ← Q(s,a) + α[r + γ·max Q(s',a') − Q(s,a)]

## Data Flow

### Simulation Mode
```
1. User configures: attacker type, detection coverage, asset criticality
2. simulation.js samples attacker technique from profile distribution
3. Detection: Bernoulli(coverage × (1 − detectionDifficulty))
4. If detected: bayesian-engine updates belief B(t)
5. bayesian-engine predicts next techniques P(t_next)
6. game-engine computes payoff matrix + ranks actions
7. rl-agent selects action (ε-greedy or game-theoretic)
8. Utilities computed, RL agent updated, state advanced
9. app.js renders: kill chain, belief bars, trace, predictions, heatmap
```

### Live IOC Mode
```
1. User pastes IOCs + selects feeds (OTX, VT, AbuseIPDB)
2. cti-manager sends POST to server.js proxy endpoints
3. server.js forwards to external APIs with API keys
4. cti-manager parses responses, extracts ATT&CK IDs
5. ioc-mapper maps enrichment → ATT&CK techniques (3 strategies)
6. live-monitor pipelines: enrich → map → Bayesian update → predict → recommend
7. app.js renders: enrichment cards, timeline, mapped techniques, predictions
```
